# NutriCore Meal AI And Fridge Sync Handoff

Last updated: 2026-08-05

This document explains the current meal-plan and meal-swap system after the recent cleanup. It is meant for any developer, reviewer, or evaluator who needs to understand how meals are generated, ranked, approved, rated, and applied in the app.

## Current Product Rule

All meal-related decisions are owned by our local modules.

Gemini is not used for:

- meal plan generation
- meal replacement
- fridge-based swaps
- recipes
- nutrition-plan decisions

Gemini may still exist for general AI chat, but the chat prompt tells it not to generate meal plans, recipes, or swaps. Meal logic belongs to NutriCore.

## Names In The UI

- Main meal system: `NutriCore`
- Refrigerator helper: `Fridge Sync`
- Approval label: `Approved`

No personal name is shown for approval. Approval is generic and comes from the meal review workflow.

## Implementation Summary

This is the full product state after the current work:

- Meal plans are generated by `NutriCore`, the local backend nutrition module.
- Gemini is not used for meal plans, meal replacements, recipes, or fridge-based swaps.
- The Nutrition Plan page can generate a normal NutriCore plan or a NutriCore plan biased by selected fridge ingredients.
- Fridge Sync is not a separate meal planner. It reads today's existing NutriCore plan, checks fridge readiness, and suggests approved swaps.
- The Fridge Sync ingredient selector was expanded with a larger catalog and category filters.
- Swap recommendations come from the local model in `src/ai/nutritionRecommendationModel.js`.
- The model ranks swaps by goal fit, macro fit, fridge match, allergies/avoided foods, user rating history, Lebanese/Arabic relevance, model score, and approval status.
- The first approved swap batch shows 10 meals. `More Approved Swaps` reveals additional approved meals without regenerating the main plan.
- User star ratings persist per user and per meal. Changing a rating replaces the old rating.
- Stars now visually reflect the saved rating: outline stars for unrated meals and filled stars for rated meals.
- The `Use Swap` button and rating stars are laid out separately so they do not overlap on small screens.
- Logged meals are protected. A completed meal cannot be replaced by a swap.
- If every meal today is logged, Fridge Sync remains browseable, but applying swaps is disabled.
- Meal approval is handled by one reviewer account only.
- Reviewer login goes directly to a simple `Meal Review` page.
- Normal users can read approval status and see approved swaps, but cannot approve meals.
- Approval is shown generically as `Approved`; no personal reviewer name is shown in the user UI.
- The documentation, migration, frontend screens, backend routes, local datasets, and validation metadata were updated for this flow.

## Main Nutrition Plan Generation

The main meal plan is generated by:

```text
backend/services/NutritionAI.php
```

The API route is:

```text
POST /api/generatePlan
body: { "type": "nutrition", "fridge_ingredients": [...] }
```

The controller is:

```text
backend/controllers/FitnessController.php
method: generatePlan()
```

The generation process:

1. Loads the authenticated user's profile.
2. Calculates target calories.
3. Calculates macro targets.
4. Reads optional `fridge_ingredients`.
5. Selects meals from the local backend food library.
6. Filters allergies and dislikes.
7. Scores meals using:
   - fridge ingredient matches
   - meal type
   - local food-library metadata
8. Saves the plan in `nutrition_plans`.

Each generated meal can include:

- `fridge_match`
- `fridge_used`
- `missing_ingredients`

These fields help Fridge Sync understand how cookable the generated plan is.

## Fridge Sync During Generation

On the Nutrition Plan screen, tapping generate opens a chooser:

- generate a standard NutriCore plan
- generate with Fridge Sync ingredients

The user can select ingredients before generation. Those ingredients are passed to the backend in `fridge_ingredients`. NutriCore then biases meal selection toward meals that use those ingredients.

This is important: Fridge Sync is not a second meal planner. It feeds into the same NutriCore plan.

## Fridge-Based Swap Model

The local recommendation model is:

```text
src/ai/nutritionRecommendationModel.js
```

It uses:

```text
src/ai/mealDataset.js
src/ai/usdaMealDataset.json
src/ai/trainedNutritionModel.json
```

The model combines:

- Lebanese custom meals
- curated local meal dataset
- USDA-backed meal dataset

It ranks candidate swaps with this idea:

```text
score =
  calorie fit
+ protein fit
+ goal fit
+ fridge ingredient coverage
+ avoided foods and allergy rules
+ persisted rating history
+ expert/model score
+ Lebanese/Arabic boost
+ approval status boost
```

Then it sorts by score and returns the top options.

Current UI limit:

```text
first 10 approved swaps
```

The user can tap `More Approved Swaps` to reveal the next approved batch. This only explores more swap options. It does not regenerate the main plan and does not affect logs or progress.

The visible list is therefore paginated:

```text
approved swaps ranked by score
        |
        v
show first 10
        |
        v
More Approved Swaps reveals the next 10
```

## Rating System

Ratings are now persisted.

Table:

```text

```

Routes:

```text
GET  /api/getMealFeedback

```

Files:

```text
backend/controllers/FitnessController.php

```

When a user rates a meal from 1 to 5, the app saves:

- user id
- meal id
- rating
- ingredients
- date/time

Rating effect:

```text
3 stars = neutral
4 stars = small boost
5 stars = bigger boost
2 stars = small penalty
1 star = bigger penalty
```

Ratings affect:

1. The exact meal.
2. Meals with similar ingredients.

UI behavior:

- unrated meals show outline stars and `Tap to rate`
- rated meals show filled stars and `Rated X/5`
- changing a rating replaces the user's previous rating for that meal
- ratings are loaded again when the screen opens

Ratings do not override approval. A highly rated meal still will not appear unless it is approved.

## Swap Application In UI

On Fridge Sync:

1. Tap an approved swap card.
2. Modal opens.
3. Choose which meal in today's plan to replace.
4. Tap `Apply To Today's Plan`.

The frontend sends an exact replacement object to:

```text
POST /api/replaceMeal
```

The backend saves that exact meal into the current nutrition plan JSON.

The UI updates immediately through:

```text
replaceMealInContext()
```

This means a swap is not just visual. It changes the actual stored plan.

### Logged Meal Locking

Fridge Sync follows the same real-life rule as coaching plans: once a meal is logged, it should not be silently changed afterward.

Current behavior:

- If a meal is not logged, it can be selected as a swap target.
- If a meal is already logged, it appears locked in the target selector and cannot be replaced.
- If all of today's meals are logged, swap browsing and star ratings remain available, but applying a swap is disabled.
- In the completed state, swap cards show `Today Done` instead of `Use Swap`.
- The modal apply button shows `Today Complete` and is disabled.

Reason:

```text
completed nutrition logs are historical progress data
```

Changing completed meals would make the user's calorie and macro history unreliable. Browsing stays enabled because the user may still want ideas for tomorrow or may want to rate meals.

## Why A Meal Appears

A meal appears in Fridge Sync only if:

1. It is manually approved.
2. It has no allergy conflict.
3. It fits the user goal enough.
4. It is reasonably close to target calories/protein.
5. It scores high against fridge ingredients, avoided foods, and saved ratings.
6. It ranks highly after scoring.

The first screen shows the first 10 ranked approved swaps. The user can reveal more approved meals with `More Approved Swaps`.

If no approved meal fits:

```text
No approved swaps yet
```

is shown.
